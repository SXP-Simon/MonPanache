哈喽大家好！我是 OceanBase 的开源研发工程师王泽霖。这次是我们第六届 OceanBase 数据库大赛的企业第二讲，这次主要讲的是阶跃星辰（StepFun）。

这次演讲大致分为三个 Part：
1. 我们为什么选择阶跃星辰；
2. 阶跃星辰的定位和主要产品是什么；
3. 这次我们和阶跃星辰合作的题目概要讲解与技术介绍。

首先为什么会有阶跃星辰的题目？最主要的原因其实是阶跃星辰提供了赞助（不仅是资金，更多是 Token 方面的赞助）。因为这次大赛和以前有很大不同：SeekDB 出了 11 个题，PowerContext 出了 11 个题，企业题出了 8 个题。这 8 个企业题都是和真实业务紧密相关的，难度比较高，也非常消耗 Token。前面的 22 个题难度不会那么难，花三四天 Agent 加上个人对数据库或 AI/向量的理解能解个七七八八，大量时间其实在这 8 个企业题上。有阶跃星辰、MiniMax、Qoder 提供大量 Token，大大减轻了大家的成本压力。

第二部分讲一下阶跃星辰的定位：
借用阶跃星辰官网的一句话：“Scale up absolutely for everyone”，把计算/大模型的能力交到每一个人手里。
主流的定位方向是：智能体时代的入口是智能终端，端云协同提供极致智能体验。现在的笔记本、PC、车机计算能力越来越强，端侧能提供更大的能力（充当数据入口、环境感知、隐私处理以及操纵本地电脑）。
阶跃星辰的核心判断是：智能终端将成为智能体时代的重要入口，而高质量的智能体体验来自端云协同：
- 端侧：更适合高频、低延迟、隐私任务（文本视觉、语音敏感信息本地处理）；弱网或断网情况下基础能力依然可用；
- 云端：更适合复杂推理和长链路任务（模型思考、逻辑推理、任务拆解、编程及多模态复杂动作）；
- 端云协同：智能判断任务简单程度，简单交端侧，复杂交云端；调度策略不仅考虑难易度，还考虑时延、隐私及 Token 成本。

端侧具备的特点：与硬件更接近（多芯片架构与 OS 兼容）、轻量化非常重要。

阶跃星辰的 1+N 大模型矩阵（Pro, Flash, Edge）：
- Pro（最高档）：Step-2，负责复杂推理与高能力任务；
- Flash（中端）：Step-1.5 / Step-1.7 Flash，面向高频、低等待、生产级 Agent 应用；
- Edge（端侧小模型）：Step-Edge 系列，面向手机/车机等智能终端本地运行；
- N 类多模态：Step-Audio、Step-Video 等覆盖音视频与图像理解。

Step-1.7 Flash 特点：面向生产级 Agent 的高效 Flash 模型，具有多模快速、好用省心四大特点（多模理解、最高 400 TPS、好用强调工具调用/编排/外部 API 浏览对接、省心优化 Agent 框架兼容性）。

第三部分：阶跃星辰赛题讲解——向量筑库（端侧 RAG）
赛题方向：考验端侧推理链路能力 + SeekDB 检索综合能力的工程。
任务：在浏览器端完成 Embedding 向量化，把数据存入 SeekDB 并提供向量检索能力。
链路流程：导入数据 -> 浏览器进行 Embedding 向量化 -> 写入 SeekDB 数据 -> 向量/全文混合检索优化。
三大核心能力：
1. 端侧量化向量化：浏览器使用轻量量化模型对文本生成向量；
2. SeekDB 索引建库：存入多类型数据，建立端侧知识库；
3. 性能调优：批处理、增量索引、索引刷新提速。

六条通用规则：
1. 端侧执行：Embedding 必须在浏览器/客户端本地执行，SeekDB 进行存储和检索；
2. 开源模型：选用开源端侧模型；
3. 可访问交付：提供交付清单（可运行 Web 应用、源码、README 说明）；
4. 兼容性：支持主流 Chromium 内核浏览器（Chrome, Edge）；
5. 降级策略：WebGPU 优先，不支持时降级至 WASM (CPU)；
6. 防作弊要求：禁止预计算回放，禁止远端模拟端侧。

推荐端侧模型：
- all-MiniLM-L6-v2（约 23MB, 8-bit int, 384维）；
- 国产模型：B-Small 中文 / 英文。

技术交付要求：
- 可运行 Web 应用（`npm run dev` 本地建站）；
- 嵌入式 SeekDB / SeekDB.js 启动脚本；
- 前后端源码及完整 README；
- doc 目录包含一份技术说明（模型来源、量化方案、SeekDB 架构、降级策略、增量与批处理优化）。
