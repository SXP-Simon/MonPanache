# 02 · 赛题方向与选题

资料核对日：2026-10-20。官方题量来自[比赛官网“赛题说明”](https://open.oceanbase.com/competition?activityCode=4924143&officerId=5045#instruction)；细分方向主要来自用户提供的培训转录。下文是**预习地图，不是完整正式题单或官方评分标准**。T01–T20 对应[材料目录](../materials/README.md)。

## seekdb：让数据库服务 AI 任务（11 题）

seekdb 是本届的数据基础设施主线；[官方仓库](https://github.com/oceanbase/seekdb)提供代码与当前用法。先建立“SQL / SDK 请求 → 数据处理与检索 → 应用或模型”的认识，再进入具体模块。

| 培训主题 | 关键问题 | 预习时应验证什么 | 材料 |
| --- | --- | --- | --- |
| AI 原生数据库基础 | 统一存储关系数据、文本、向量等，如何支撑 Agent | 能说明写入、索引与查询的关系，分清服务模式和嵌入式模式 | T05 |
| 向量数据库与 RAG | 语义召回、关键词召回、过滤与重排如何配合 | 用少量已知答案的问题比较检索结果；不要只看生成回答是否流畅 | T06 |
| AI Functions | 将模型能力接入 SQL 执行链路 | 参数校验、模型端点、协议适配、返回值与异常处理 | T07 |
| File SQL | 让 Agent 直接查询文件，减少导入与临时建表步骤 | 格式解析、Schema 推断、路径边界、JOIN 和端到端结果 | T08 |
| AI 列 | 源数据变化后，模型派生结果如何可靠更新 | 回滚、并发、过期结果、失败重试、恢复与索引一致性 | T09 |

T07 提到的函数包括 `AI_EMBEDDING`、`AI_RERANK`、`AI_COMPLETE`；培训预告包括类型 / 协议扩展、错误处理和批量执行。不要据此编造正式题号、分值或接口签名。

T08 的 File SQL 语法展示及 T09 的 AI 列 DDL 都有版本前提。本次不将转录中的示例整理为“复制即能运行”的命令；实现时以赛题分支源码和测试为准。

**适合的基础**：C++、SQL、调试、测试、数据库原理。建议先追一条请求的执行链路，再选较小功能；异步 AI 列涉及的状态与一致性问题更多，可留作深入方向。这是学习难度判断，不代表官方难度等级。

## PowerContext：让任务上下文持续可用（11 题）

PowerContext 从 PowerMem 演进而来；[官方仓库](https://github.com/oceanbase/powercontext)强调跨会话的工作接续。培训 T10–T12 用三个概念组织内部流程：

| 概念 | 可以怎样理解 | 需要关注的工程问题 |
| --- | --- | --- |
| Source（来源） | 对话、文档、代码、日志等原始证据 | 来源、时间、版本、权限和可回溯性 |
| Artifact（制品） | 从来源提取的记忆、经验、画像、Skills 等 | 是否忠实、是否过时、是否互相冲突 |
| Trigger（触发） | 决定何时提取、更新或注入上下文 | 生命周期、任务边界、重复处理与成本 |
| Context Pack | 按任务和预算组织的上下文组合 | 相关性、Token 预算、排序与适用范围 |
| Handoff（交接） | 把目标、约束、进展、阻塞和下一步交给接手者 | 接手者能否继续工作，能否核查证据 |

官网列出的预习范围包括多源接入与结构化、检索和排序、长期记忆、冲突处理、压缩与预算控制、Agent 场景中的动态上下文编排。学习时把它看作一条链：

```text
采集来源 → 提取与更新制品 → 检索/排序 → 按预算组装上下文
     ↑                                      ↓
  新证据与执行反馈 ← 评估任务结果 ← Agent 执行或交接
```

**建议自测场景**：同一项目先要求保留一个旧接口，之后只修改另一条需求；切换到新会话后，检查 Agent 是否仍能保留有效约束、识别已失效要求、找到测试并完成任务。对比不用上下文工具时的结果，同时记录 Token、耗时与失败案例。T12 的评估讨论可帮助设计这种对照，但不是本届官方评分公式。

**适合的基础**：数据建模、检索、Agent 工作流、Python / 服务集成、评估设计。不要把“保存全部历史”当作完成目标；需要证明正确的信息在正确的任务中被使用。

## AI 生态：8 家方向，各 1 题

以下仅归纳培训实际披露的内容。“建议先做的验证”是本仓库的学习建议。部分课程没有公布具体题面，明确保留未知项。

| 合作方 | 转录讲了什么 | 建议先做的验证 | 正式规则仍需确认 | 材料 |
| --- | --- | --- | --- | --- |
| AMD | seekdb 经兼容接口接入 hipVS / ROCm，加速向量检索；批量规模影响 CPU / GPU 收益 | 比较不同 batch 下的延迟、吞吐与结果质量 | 指定代码、硬件、数据集、计分口径、算力领取 | T13 |
| 阶跃星辰 | 浏览器 / 客户端本地 Embedding，写入 seekdb，完成检索；预告 WebGPU 与 WASM 降级 | 证明向量确实在本地生成，并跑通导入、索引与检索 | 模型许可与版本、浏览器、数据库部署方式、最终交付 | T14 |
| 高德 | 持续进化的个人位置智能体；旅行规划、空间数据、偏好与反馈 | 路线能满足时间与空间约束，修改偏好后能重新规划 | API 配额、数据范围、记忆要求、评价方式 | T15 |
| Dify | Workflow、Agent、知识库、可观测性及数据库集成 | 用最小工作流完成检索、输出和一次失败定位 | 本份转录未明确给出最终题名、必做功能或评分项 | T16 |
| 原力灵机 | HandPose 数据结构化，沉淀经验样本，用相似 / 质量 / 缺口检索指导补采 | 从样本追到原证据，并给出可解释的补采建议 | 数据集、硬件要求、是否修改内核、评价指标 | T17 |
| Qoder | 用 AI 工具完成调研、开发、验证、打包和汇报；演示对账工作台 | 保存设计、代码差异、真实数据库验证与演示 | 演示不等于正式题目；产品形态、技术栈及交付要求待定 | T18 |
| 魔搭 | 领域智能体与开源成果；预告创空间 Demo、至少一种开源资产、技术实践文档 | 先明确领域场景、可复用资产及演示方式 | 培训中领域方向尚未披露；发布要求以正式题面为准 | T19 |
| MiniMax | SDD 工程上下文工具：关联需求、设计、代码、测试，维护有效要求并支持持续研发 | 对比接入前后约束遗漏、连续修改一致性、交接后的测试结果 | 可复用 Agent / 项目范围、数据集、模型与评分要求 | T20 |

对 MiniMax 方向，T20 给出的核心交付思路比较明确：可运行工具与说明、完整开发演示、代码差异、测试结果、上下文来源。核心是给现成 Agent 提供可靠工程依据；不应擅自把范围扩大成重新开发一个通用编程 Agent。

对原力灵机方向，T01 曾笼统提到偏底层题；T17 具体课程主要讲采集闭环。因此本指南不把“必须修改 seekdb 内核”写为已确定要求。

## 怎么选第一条学习主线

| 当前兴趣或已有经验 | 建议先读 | 第一个可验证成果 |
| --- | --- | --- |
| 喜欢 C++、系统和数据库 | T05 → T07，必要时补 MiniOB | 解释执行链路，定位一个功能及相关测试 |
| 喜欢 Agent 记忆和长期任务 | T10 → T11 → T12 | 一个带来源的交接样例与对照评估 |
| 熟悉软件工程、文档与自动化 | T20 → T10–T12 | 需求到代码、测试的关联样例 |
| 熟悉 Web 或应用开发 | T14 / T15 / T16 / T18 | 数据库参与的最小端到端场景 |
| 已有 GPU 或具身数据经验 | T13 / T17 | 可复现实验与结果分析 |
| 想做可复用开源成果 | T19，再选具体领域 | Demo、资产和技术文档的交付草案 |

当前尚无完整分值、依赖和评分细则，不能可靠地给出“哪题最容易高分”的排名。建议先选一条主线验证环境和能力，正式题目公布后再按收益、实现成本及资源限制排序。
