## 本地材料登记

用户提供的“转录文本汇总”目录共包含 **20 份 TXT、20 份 SRT 和 1 个 ZIP**。

- TXT 和 SRT 原样归档，原文件名不变。
- ZIP 是用户提供的另一份打包文件，本次没有解包或比较其成员；为避免重复材料，未纳入 Git。
- [材料目录](../materials/README.md)用 T01–T20 编号链接到各讲。
- [manifest.json](../materials/manifest.json)记录每个归档文件的字节数与 SHA-256，便于和原目录核对。
- SRT 的“时长”取最后一条字幕的结束时间，只代表字幕覆盖到的位置，不保证是视频总时长。
- 部分 TXT 是精简文本；未把 TXT 与 SRT 当作逐字一致版本，也未重新润色原文。
- 原视频链接、视频发布日期及转录工具未随文件一并提供，本次不猜测补写。

## 仍需向当届正式规则确认

| 待确认内容 | 为什么会影响行动 |
| --- | --- |
| 各题完整题面、分值、依赖和评分方式 | 决定实际选题优先级 |
| seekdb / PowerContext 指定仓库、分支、版本 | 防止在错误基线上实现 |
| 提交仓库是否私有、账号与权限、提测步骤 | 决定实现代码放在哪里以及如何评测 |
| 报名与初赛截止的具体时分 | 防止把日期误解成当天 23:59 |
| 决赛具体日期、地点、形式与现场要求 | 决定后续安排；启动仪式的马拉松构想不是最终通知 |
| 中学生资格、跨校组队、本科生队伍认定 | 公开资料与完整报名条件尚未逐项核实 |
| AI 使用、外部代码、数据与成果公开要求 | 决定允许复用的范围以及应提交的说明 |
| Token / GPU 的领取入口、额度和有效期 | 决定成本和环境可用性；不以培训历史数字做预算 |
| 生态题中演示、开源、模型、硬件等具体限制 | 防止做出能运行但不符合题面要求的作品 |

更新这些条目时，同时记录官方链接、查看日期和影响到的文档。正式规则变化优先更新比赛速览与 README，再改阅读计划。
