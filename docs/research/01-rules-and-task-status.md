## 2. 初赛是否要选方向

**当前证据支持按方向安排学习和分工，不支持“报名后只能做某一类题”的断言。** 官网以三类题和总分描述初赛，但未在本次可见内容中明确互斥选择、跨类计分上限、必做题或最低完成数量。

因此可采用以下工作方式：先选择主攻模块以减少学习成本；正式题单可见后，再按题目依赖、分值和完成概率挑题。不能进一步推断“可以无条件跨方向提交”“三条线全部必须完成”或“挑任意一题即可晋级”。

## 3. 初赛形式如何理解

官网描述的是持续提交与评测的工程实践平台。准备工作应覆盖获取指定代码、构建、实现、运行测试、提交与读取反馈。公开说明没有给出所有任务的评审细节：生态作品可能还涉及演示或材料，但本报告不把这种可能性写成已确认规则。

建议准备的交付物是：固定 commit 的代码、可复现环境说明、测试记录、实验结果、设计解释和短演示。这是通用备赛建议，不代表正式提交格式已经确定。

## 5. 实际访问情况

- 官网“查看课程”链接到 [2026 从 0 到 1 数据库实践教程](https://open.oceanbase.com/course/850)，显示 20 节；点击学习提示登录。公开目录足以核对本地转录标题，不能据此确认视频逐字一致。
- 官网“提测平台”链接到 [训练营入口](https://open.oceanbase.com/train?questionId=200001)。本次未登录状态显示 MiniOB 训练营和 2025 赛事等列表，没有看到本届完整题单。
- 两个官方仓库存在 `2026-competition` 分支；另有 PowerContext `2026-competition-ecosystem`。后者本次目录仅有五家伙伴的占位文件，没有正式题面。

这些是访问范围说明，不等于“题目肯定尚未发布”。题目可能需要登录、报名身份或后续入口才能查看。

## 6. 正式题面出现后必须登记的字段

| 字段 | 为什么影响选题 |
| --- | --- |
| 题号、题名、分值、类别 | 防止把培训话题当题目，才能计算投入顺序 |
| 指定仓库、分支、commit、依赖版本 | 决定哪些已有功能可用、是否允许修改依赖 |
| 功能要求与边界输入 | 决定正确性测试，不以演示样例代替规范 |
| 公开测试、隐藏测试说明、评分函数 | 区分按通过率、质量、性能或作品评审计分 |
| 硬件、超时、内存、网络与模型限制 | 决定 GPU、外部服务和缓存是否可用 |
| 数据集、训练／开发／测试边界 | 防止调参污染测试集 |
| 提交格式、队长权限、频率与队列限制 | 影响日常提测安排 |
| 最佳成绩还是最后成绩、并列规则 | 影响临近截止时提交风险 |
| 开源、引用、第三方依赖与 AI 使用披露要求 | 决定交付文档内容 |
| 精确截止时间及更正通知 | 避免错过窗口 |

## 7. 避免混入其他年份

MiniOB 是很好的数据库基础项目，但旧 MiniOB 初赛、seekdb 决赛的规则不能套到本届。当前官网下方仍引用往届报道；识别时应看具体年份和赛事阶段，而不是只看页面域名。

另查到 seekdb issue #123 的 2026 年 1 月社区开发活动，时间、活动目的均不同，未作为本届评分依据。[该活动原帖](https://github.com/oceanbase/seekdb/issues/123)

建议只补与当前任务有关的 MiniOB 知识：SQL 解析、算子执行、类型与 NULL、索引、事务和恢复。不要为了“先学完数据库”推迟实际构建与测试。
