# 第六届 OceanBase 数据库大赛：赛题与优化研究

研究日期：**2026-10-23，北京时间**。本报告用于选题、理解实现边界和设计实验；没有宣称已经完成赛题、运行基准或获得官方分数。

## 先读结论

1. **官网题量已更新：seekdb 12 题、PowerContext 11 题、AI 生态 7 题，共 30 题、620 分。** 10 月 20 日整理和培训材料中的 11／11／8 已不是当前官网口径。当前生态名单为 AMD、MiniMax、Qoder、阶跃星辰、Dify、高德、魔搭；原力灵机仍有培训材料，但不在当前七家名单中。仅凭名单变化，不能判断旧方向被取消、合并还是移入 seekdb。[当前官方赛题说明图](https://mdn.alipayobjects.com/huamei_22khvb/afts/img/A*WY7oRLa9-iYAAAAAgCAAAAgAeiGDAQ/original)
2. **先选主攻方向是备赛策略，尚不能认定报名必须三选一。** 官网描述按总分排名；本次公开访问没有找到“只能做一个方向”的明确规则，也没有取得跨方向限制和完整计分细则。可以先准备一条主线，再依据正式题面决定兼做范围。[比赛官网](https://open.oceanbase.com/competition?activityCode=4924143&officerId=5045)
3. **已经提取了赛题解析课程，但没有拿到完整 30 道正式题面。** 本地 20 讲与官网 20 节课程标题对应，包含数据库、上下文工程及八家伙伴解析。官方课程页要求登录后学习；公开提测入口本次仍展示往届训练营。因此本报告明确区分官网概述、课程预告、代码现状和研究建议。[课程目录](https://open.oceanbase.com/course/850) · [原始材料索引](../../materials/README.md)
4. **两大官方仓库都有 `2026-competition` 分支。** 已锁定研究 commit，核查关键代码。分支名称本身不能证明提测平台最终要求从哪个 commit 开始。[源码地图](05-code-map.md)
5. **优化首先是正确性与可测性，其次才是速度。** 模型调用要考虑请求合并、失败重试和结果归位；文件查询要考虑类型和谓词语义；AI 列要考虑旧结果回写；上下文检索要考虑证据、权限、时效和预算。没有统一基线的“快了几倍”无法判断价值。

## 如何读本报告的结论

| 标签 | 含义 | 能否直接当评分要求 |
| --- | --- | --- |
| 官网确认 | 当前官网公开文字或图示明确写出 | 仅限实际写出的范围 |
| 代码确认 | 固定 commit 下文件或实现已核查 | 不能据此推导官方赛题 |
| 培训预告 | 用户提供的课程转录介绍过 | 正式题面发布后必须复核 |
| 研究建议 | 本报告提出的实现、实验或选题方法 | 不能 |
| 待确认 | 尚未取得可核验信息 | 不能用猜测填补 |

全文中“建议”“可尝试”“基线”“自测”均属于研究建议。各章节的主题编号不是官方题号；也没有把 12 或 11 题强行拆成虚构标题。

## 当前最值得做的三件事

- 用固定版本建立最小可运行环境，记录构建和首次成功调用；优先让队友能够复现。
- 选一个有明确输入、输出和失败条件的模块，建立回归样例，再做一个可关闭的优化。
- 正式题面可见后立即补齐题号、分值、基线、限制、提交格式和截止时刻，用正式规则调整投入顺序。
